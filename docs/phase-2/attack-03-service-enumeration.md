# Attack 03 – HTTP Service Enumeration

## Objective

Identify the service, software, and version running on the target's open HTTP port while observing the additional network activity generated by service enumeration.

---

## Environment

| System | Role | IP Address |
|---------|------|------------|
| Kali Linux | Attacker | 10.0.2.4 |
| Ubuntu | Victim | 10.0.2.15 |

**Network:** VirtualBox NAT Network

---

## Attack Overview

After identifying an open port, an attacker attempts to determine what application is running behind it. This process, known as service enumeration, provides valuable information about the target system and helps prioritize potential attack paths.

Unlike a TCP SYN scan, service enumeration interacts directly with the application to identify software and version information.

---

## Attack Method

### Manual Verification

The HTTP service was first verified manually using:

```bash
curl http://10.0.2.15
```

The response displayed the default Apache2 Ubuntu page, confirming that an Apache web server was accessible on TCP port 80.

---

### Automated Enumeration

Nmap service version detection was performed using:

```bash
sudo nmap -sV 10.0.2.15
```

---

## Scan Results

```
PORT   STATE SERVICE VERSION
80/tcp open  http    Apache httpd 2.4.58 ((Ubuntu))
```

Nmap successfully identified:

- Service: HTTP
- Server: Apache HTTP Server
- Version: 2.4.58
- Operating System Hint: Ubuntu

---

## Packet Capture

Capture file:

```
captures/phase-2/attack-03/service_enumeration.pcap
```

Traffic captured using:

```bash
sudo tcpdump -i eth0 -w service_enumeration.pcap
```

---

## Observed Network Artifacts

Observed protocols included:

- TCP
- HTTP
- ARP (background)
- DHCP (background)

Compared to the previous SYN scan, significantly more packets were generated because Nmap actively communicated with the HTTP service to identify the application.

Packet statistics:

- Approximately **2,157 packets captured**

---

## Information Gained

The attacker successfully determined:

- The host provides an HTTP service.
- Apache HTTP Server is running.
- Apache version 2.4.58 is installed.
- The server is likely running Ubuntu.
- The default Apache landing page is still present.

This demonstrates how service enumeration provides substantially more intelligence than simple port scanning.

---

## Defender Perspective

A defender monitoring network traffic would observe:

- Multiple application-layer requests
- HTTP communication between attacker and victim
- Numerous TCP connections generated by service detection
- Traffic volume significantly higher than a basic SYN scan

Unlike a port scan, service enumeration leaves richer application-layer evidence that is easier to investigate.

---

## Detection Opportunities

Possible detection indicators include:

- HTTP requests with unusual headers or probe patterns
- High number of short-lived TCP connections
- Automated fingerprinting behavior
- Repeated requests originating from a single source host
- Network traffic inconsistent with normal user browsing

---

## Limitations

Service enumeration identifies software and version information but does not confirm whether the service is vulnerable.

Additional validation is required before concluding that a vulnerability exists.

---

## Key Takeaways

- Service enumeration follows port discovery during attacker reconnaissance.
- Manual verification provides initial insight into exposed services.
- Automated version detection reveals additional information such as software name and version.
- Application-layer enumeration generates considerably more network evidence than a SYN scan.
- Accurate service identification helps both attackers and defenders understand the target environment.
